## 摘 要

随着互联网社交平台的普及，社区论坛系统已成为用户交流和信息分享的基础设施。本项目设计并实现了一个基于前后端分离架构的极简微博仿制论坛系统，采用 Java 21 + Spring Boot 3.3.5 作为后端框架，Vue 3 + Element Plus 作为前端框架，MySQL 8 作为业务数据库，并引入 Spark 4.1.2 进行离线数据分析。

系统实现了用户注册登录（JWT + BCrypt 认证）、板块浏览与管理、帖子发布与搜索、两级评论（树形展示）、通用点赞模型、管理后台（用户管理/板块管理/内容管理/数据统计可视化）等核心功能。后端共设计 43 个 RESTful API 端点，前端共实现 15 个页面组件和 8 个公共组件，自动化测试覆盖 67 个用例（通过率 100%）。

Spark 离线分析模块每日定时跑批，从业务表聚合数据写入 6 张统计表，为前端数据统计页面提供趋势图、饼状图、柱状图三种可视化展示，并支持手动触发跑批与状态轮询。

通过本项目实践，完整展示了软件工程从需求分析、系统设计、编码实现到测试部署的全流程，验证了前后端分离架构在团队协作开发中的有效性。

**关键词**：Spring Boot；Vue 3；前后端分离；Spark 离线分析；JWT 认证

## 1. 项目概述

### 1.1 项目背景

在现代互联网环境中，社区论坛和微博类平台已成为人们获取信息、交流观点的重要渠道。尽管市面上已存在成熟的社交平台（如微博、贴吧等），但对于课程教学和前后端分离架构实践而言，一个结构清晰、规模可控的"最小可用"论坛系统具有重要的学习价值。

本项目面向软件工程课程设计，目标是构建一个极简微博仿制论坛系统，去除关注、私信、复杂推荐、用户自建板块等高复杂度功能，聚焦论坛核心业务闭环：

```
注册 → 登录 → 浏览板块 → 查看帖子 → 发布帖子 → 评论互动 → 点赞 → 管理员管理
```

### 1.2 项目目标

1. 实现完整的用户认证体系（注册、登录、JWT 鉴权、BCrypt 密码加密）
2. 构建论坛核心业务流程（板块、帖子、评论、点赞的增删改查）
3. 实现管理后台（用户管理、板块管理、内容审核、数据统计可视化）
4. 集成 Spark 离线分析引擎，提供论坛数据趋势分析与排行
5. 建立代码规范、测试标准和完善的项目文档体系

## 2. 系统设计

### 2.1 系统设计思路

#### 2.1.1 整体架构

系统采用**前后端分离**架构，前端通过 HTTP RESTful API 与后端通信，后端通过 MyBatis Plus 访问 MySQL 数据库。Spark 离线分析模块作为独立进程，通过 JDBC 读取业务表数据进行聚合计算，将结果写入统计表供后端只读展示。

```text
┌─────────────────────────────────────────────────────┐
│                    前端 (Vue 3)                       │
│   Element Plus + Axios + ECharts + Pinia + Router    │
└─────────────┬───────────────────────────────────────┘
              │  HTTP REST API (JSON)
              │  JWT Bearer Token 认证
┌─────────────▼───────────────────────────────────────┐
│                 后端 (Spring Boot 3.3.5)              │
│  Controller → Service → Mapper → MySQL               │
│  Spring Security + JWT + BCrypt + MyBatis Plus       │
└──────┬──────────────────────────────┬───────────────┘
       │ 业务数据读写                   │ 只读统计表
┌──────▼──────────┐    ┌──────────────▼───────────────┐
│  MySQL (业务表)  │    │    MySQL (统计表 stat_*)       │
│  sys_user       │◄───│    stat_overview              │
│  forum_board    │    │    stat_hot_post              │
│  forum_post     │ 写入│    stat_board_active          │
│  forum_comment  │    │    stat_active_user           │
│  forum_like     │    │    stat_content_quality       │
└─────────────────┘    │    stat_daily_trend           │
                        └──────────▲──────────────────┘
                                   │ JDBC 写入
                        ┌──────────┴──────────────────┐
                        │  Spark 离线分析 (独立进程)    │
                        │  cron 每日 03:00 定时跑批     │
                        │  或手动 POST 触发 / 轮询状态  │
                        └─────────────────────────────┘
```

#### 2.1.2 设计原则

1. **前后端分离**：前端 Vue 3 单页应用独立部署，通过 REST API 与后端解耦
2. **分层架构**：后端遵循 Controller → Service → Mapper → MySQL 四层结构，职责清晰
3. **安全优先**：BCrypt 密码加密、JWT 无状态认证、Spring Security 接口级鉴权
4. **通用模型**：点赞采用 `(targetType, targetId, userId)` 三元组，支持帖子和评论统一点赞
5. **读写分离**：统计展示不查业务表，由 Spark 独立写入统计表，避免分析查询影响在线业务
6. **SQL 集中管理**：所有 SQL 统一写在 Mapper XML 中，不散落在注解或代码里

### 2.2 数据库设计

#### 2.2.1 E-R 图

系统包含 5 张核心业务表 + 6 张统计表（由 Spark 跑批写入），其 E-R 关系如下：

```text
┌──────────┐        ┌──────────────┐        ┌──────────────┐
│  sys_user│ 1    N │  forum_post  │ 1    N │forum_comment │
│──────────│◄───────│──────────────│◄───────│──────────────│
│ userId PK│        │ postId PK    │        │ commentId PK │
│ username │        │ boardId FK ──┐        │ postId FK    │
│ password │        │ authorId FK  │        │ userId FK    │
│ nickname │        │ title        │        │ parentId     │
│ role     │        │ content      │        │ replyUserId  │
│ status   │        │ viewCount    │        │ content      │
└──────────┘        │ likeCount    │        │ likeCount    │
     │              │ commentCount │        └──────────────┘
     │              │ isTop        │               │
     │ 1            └──────┬───────┘               │
     │                    │                       │
     ▼              ┌──────▼───────┐               │
┌─────────┐         │ forum_board  │               │
│forum_like│        │──────────────│               │
│─────────│         │ boardId PK   │               │
│ likeId PK│        │ boardName    │               │
│targetType│        │ description  │               │
│ targetId │        │ sortNum      │               │
│ userId FK│        │ status       │               │
└─────────┘         └──────────────┘               │
     │                                             │
     └─────────────── 通用点赞 ─────────────────────┘
          targetType=1(帖子) / targetType=2(评论)
```

#### 2.2.2 关系模式

**业务表（5 张）：**

- **sys_user**(userId, username, password, nickname, avatar, signature, role, status, createTime, updateTime)
- **forum_board**(boardId, boardName, description, sortNum, status, createTime, updateTime)
- **forum_post**(postId, boardId, authorId, title, content, viewCount, likeCount, commentCount, isTop, status, createTime, updateTime)
  - FK: boardId → forum_board(boardId)
  - FK: authorId → sys_user(userId)
- **forum_comment**(commentId, postId, userId, parentCommentId, replyUserId, content, likeCount, status, createTime, updateTime)
  - FK: postId → forum_post(postId)
  - FK: userId → sys_user(userId)
  - FK: parentCommentId → forum_comment(commentId)
- **forum_like**(likeId, targetType, targetId, userId, createTime)
  - UNIQUE: (targetType, targetId, userId) — 同一用户对同一目标不可重复点赞
  - FK: userId → sys_user(userId)

**统计表（6 张，Spark 写入，后端只读）：**

- **stat_overview** — 总体概览（用户/板块/帖子/评论/点赞总数 + 活跃用户数 + 更新时间）
- **stat_hot_post** — 热门帖子排行（排名 + 帖子信息 + 热度分 = 点赞×2 + 评论×3 + 浏览×0.1）
- **stat_board_active** — 板块活跃度（帖子数/浏览总量/点赞总量/评论总量/活跃度分）
- **stat_active_user** — 用户活跃度排行（发帖/评论/获赞数/活跃度分）
- **stat_content_quality** — 内容质量（HIGH_LIKE_LOW_COMMENT / HIGH_COMMENT_LOW_LIKE / HOT 三分类）
- **stat_daily_trend** — 每日趋势（日期 + 新增用户/帖子/评论/点赞数）

### 3.2 后端核心模块

#### 3.2.1 用户认证模块

**技术栈**：Spring Security 6.x + JWT + BCrypt

**核心流程**：

1. **注册**：`POST /auth/register` → 校验用户名唯一性 → BCrypt 加密密码 → 强制设置 `role=USER` → 插入数据库
2. **登录**：`POST /auth/login` → 查询用户 → BCrypt 验证密码（兼容明文兜底）→ 生成 JWT（含 userId + role，有效期 24h）→ 返回 `{ token, user }`
3. **鉴权**：`JwtAuthenticationFilter` 拦截所有非公开请求 → 从 `Authorization: Bearer <token>` 头解析 JWT → 获取 userId/role 注入 SecurityContext
4. **权限**：`SecurityConfig` 集中管理：`/auth/**` 公开；`/admin/**` 仅 ADMIN；其余需认证

**实现要点**：

- BCrypt 强度设为 10，登录时兼容明文密码的兜底比较（用于兼容未加密的历史数据）
- JWT 密钥从环境变量 `JWT_SECRET` 注入，不写死在仓库中
- 所有 Controller 通过 `SecurityUtil.getCurrentUserId()` 获取当前用户，不信任请求体中的 userId

@Override
protected void doFilterInternal(HttpServletRequest request,
        HttpServletResponse response, FilterChain chain)
        throws ServletException, IOException {
    String header = request.getHeader("Authorization");
    if (header != null && header.startsWith("Bearer ")) {
        String token = header.substring(7);
        Claims claims = jwtUtil.parseToken(token);
        // 将 userId 和 role 注入 Spring Security 上下文
        SecurityContextHolder.getContext().setAuthentication(
            new UsernamePasswordAuthenticationToken(claims, null, authorities));
    }
    chain.doFilter(request, response);
}

#### 3.4.2 评论树构建算法

```java
// ForumCommentServiceImpl.getComments() — 内存构建两级评论树
public List<ForumComment> getComments(Integer postId) {
    List<ForumComment> all = commentMapper.getCommentsByPostId(postId);
    Map<Integer, ForumComment> rootMap = new LinkedHashMap<>();
    List<ForumComment> roots = new ArrayList<>();
    
    // 第一遍：初始化 children 列表，收集根评论
    for (ForumComment c : all) {
        c.setChildren(new ArrayList<>());
        if (c.getParentCommentId() == null) {
            rootMap.put(c.getCommentId(), c);
            roots.add(c);
        }
    }
    // 第二遍：子评论挂载到父评论的 children 列表中
    for (ForumComment c : all) {
        if (c.getParentCommentId() != null) {
            ForumComment parent = rootMap.get(c.getParentCommentId());
            if (parent != null) {
                parent.getChildren().add(c);
            } else {
                roots.add(c);  // 孤儿评论降级为根评论
            }
        }
    }
    return roots;
}
```

#### 3.4.4 Spark 并发控制

```java
// SparkStatsServiceImpl — AtomicReference CAS 保证单任务
public Map<String, Object> triggerRun() {
    if (!sparkEnabled) return Map.of("state", "DISABLED");
    
    RunState current = lastRun.get();
    if (current != null && current.getState() == State.RUNNING) {
        return current.toMap();  // 已有任务运行
    }
    RunState running = RunState.running(UUID.randomUUID().toString());
    if (!lastRun.compareAndSet(current, running)) {
        return lastRun.get().toMap();  // CAS 失败，已被其他线程抢占
    }
    new Thread(this::executeSpark).start();  // 异步执行
    return running.toMap();
}
```

http.interceptors.response.use(
  response => {
    const { code, message, data } = response.data
    if (code === 200) return data          // 成功，返回 data
    ElMessage.error(message)
    return Promise.reject(new Error(message))
  },
  error => {
    if (error.response?.status === 401) {  // token 失效

  }

## 5. 已知问题与优化建议

### 5.1 已知问题

| 序号 | 问题 | 影响范围 | 严重程度 |
|------|------|---------|:--------:|
| 1 | 评论删除不级联子评论 | 子评论仍保留但父评论为 null | 低 |
| 2 | UserServiceImpl.deletePost() 缺少评论/评论点赞级联删除 | 个人中心删帖后残留评论数据 | 中 |
| 3 | 板块删除不级联帖子 | 板块删了但帖子还在 | 低 |
| 4 | 登录密码兼容明文兜底逻辑存在安全风险 | 若历史未加密密码遭泄露 | 中 |
| 5 | 跑批轮询无总超时上限 | 已在前端补 5 分钟兜底 | 已修复 |
| 6 | StatisticsPage 无单元测试 | 页面复杂度高，回归依赖人工 | 低 |

### 5.2 优化建议

1. **统一级联删除**：评论删除时同时清理子评论；UserService.deletePost() 复用 ForumPostService.deletePost() 的完整级联逻辑
2. **去除明文密码兜底**：移除登录逻辑中的 `rawPassword.equals(storedPassword)` 兜底比较，确保所有密码均经 BCrypt 加密
3. **接口限流**：对登录和点赞等高频接口增加 Rate Limiting（如 Guava RateLimiter 或 Spring Cloud Gateway）
4. **前端懒加载拆分**：ECharts 改为 `import('echarts')` 动态加载，将 StatisticsPage 块从 519K 降至 < 200K
5. **数据库索引优化**：为 `forum_post.boardId`、`forum_comment.postId`、`forum_like.userId` 添加索引
6. **补充前端单元测试**：使用 Vitest + Vue Test Utils 覆盖 StatisticsPage 的轮询状态机和图表渲染逻辑
