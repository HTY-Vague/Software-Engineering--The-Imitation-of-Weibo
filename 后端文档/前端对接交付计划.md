## 一、任务需求摘要

1. **既有接口结构调整**：`GET /admin/statistics/hot-posts` 返回从 `ForumPost` 列表

3. **新增 2 个跑批管理接口**：触发跑批（POST）、查询状态（GET），需要前端实现
   "点击触发 → 轮询状态 → 完成后重载" 的人机交互闭环。

## 三、技术实现要点

### 3.1 M1 接口封装

按待办清单推荐做法，把 8 个统计接口集中到 `services/modules/statistics.js`，
并对 `admin.js` 中的重复定义做去重注释，引导后续引用方改路径：

- `getOverview` / `getHotPosts` 已迁移至 `statistics.js`
- 新增：`getBoardActive` / `getActiveUsers` / `getContentQuality` /
  `getDailyTrend` / `triggerSpark` / `getSparkStatus`
- 同时修复 `pages/admin/PostsPage.vue` 中从 `admin.js` 误引 `getHotPosts` 的回归

### 3.2 M2 数据装配

- 7 个接口首次进入页面用 `Promise.all` 并发加载，提升首屏速度。
- `updateTime` 字段从所有可能的返回里取"最近一个"，展示给用户"最近更新于 xxx"。
- Spark 跑批轮询用 `setInterval(2000ms)`，**仅在 `RUNNING` 时继续轮询**，
  终态（`SUCCESS / FAILED / DISABLED`）清除定时器并切换按钮 loading。
- 组件销毁时清理：定时器、ECharts 实例、`window.resize` 监听器，避免内存泄漏。

### 3.3 M3 可视化与交互

- 引入 `echarts@5.5.1`（按文档建议），用按需引入的方式缩减体积：
  `LineChart + GridComponent + TooltipComponent + LegendComponent + CanvasRenderer`。
- 趋势图按 `statDate` 升序展示（后端默认降序），用 `localeCompare` 排序避免时区问题。
- 内容质量分类用 `el-tabs` 切换，分类标签用 `el-tag` 着色：
  - `HIGH_LIKE_LOW_COMMENT` → success 绿
  - `HIGH_COMMENT_LOW_LIKE` → warning 橙
  - `HOT` → danger 红
- 热门帖子从 `PostCard` 改为排行表格，重点突出 `rankNum` 和 `hotScore`。
- 按钮防重复：刷新统计按钮 `:loading="refreshing" :disabled="refreshing"`。

### 3.4 工程问题修复（联调过程中发现并修复）

| 问题 | 根因 | 解决 |
|------|------|------|
| `npm run build` 报 lightningcss 伪元素空白错误 | Vite 8 默认 CSS 压缩器 lightningcss 对 scoped CSS 中带属性选择器与 `::v-deep` 风格的产物解析失败 | `vite.config.js` 设置 `build.cssMinify: 'esbuild'`；同时 `npm i -D esbuild` |
| `PostsPage.vue` import 不到 `getHotPosts` | 之前重复定义在 `admin.js`，本次清理后引用断链 | 改 import 路径为 `services/modules/statistics` |
| CSS 中 `.title + .meta` 相邻选择器被 lightningcss 拒绝 | 同 lightningcss 问题 | 改用语义化类名 `.title-meta` 替代 |

## 八、接口定义汇总（按 `API接口清单.md` 同步约定）

> 以下表格与 `API接口清单.md` v1 一致；列宽固定，便于前后端对照。

### 8.1 已存在 / 已变更

| 方法 | 路径 | 鉴权 | 请求 | 响应 data | 前端使用 |
|------|------|------|------|-----------|----------|
| GET | `/admin/statistics/overview` | ADMIN | — | `StatOverview{userCount,activeUserCount,enabledBoardCount,postCount,commentCount,likeCount,updateTime}` | 概览卡片 |
| GET | `/admin/statistics/hot-posts?limit=` | ADMIN | `{limit:int<=50}` | `StatHotPost[]{rankNum,postId,boardId,authorId,title,viewCount,likeCount,commentCount,hotScore,updateTime}` | 热门帖子排行表 |

### 8.2 新增 4 个分析接口

| 方法 | 路径 | 鉴权 | 请求 | 响应 data | 前端使用 |
|------|------|------|------|-----------|----------|
| GET | `/admin/statistics/board-active` | ADMIN | — | `StatBoardActive[]{boardId,boardName,postCount,viewSum,likeSum,commentSum,activeScore,updateTime}` | 板块活跃度表 |
| GET | `/admin/statistics/active-users?limit=` | ADMIN | `{limit:int<=50}` | `StatActiveUser[]{rankNum,userId,username,nickname,postCount,commentCount,likeCount,activeScore,updateTime}` | 用户活跃度表 |
| GET | `/admin/statistics/content-quality?qualityType=` | ADMIN | `{qualityType?:'HIGH_LIKE_LOW_COMMENT'\|'HIGH_COMMENT_LOW_LIKE'\|'HOT'}` | `StatContentQuality[]{postId,title,likeCount,commentCount,viewCount,qualityType,updateTime}` | 内容质量 Tab |
| GET | `/admin/statistics/daily-trend?days=` | ADMIN | `{days:int<=90,默认7}` | `StatDailyTrend[]{statDate,newUserCount,newPostCount,newCommentCount,newLikeCount,updateTime}` | ECharts 折线图 |

### 8.3 新增 2 个跑批管理接口

| 方法 | 路径 | 鉴权 | 请求 | 响应 data | 前端使用 |
|------|------|------|------|-----------|----------|
| POST | `/admin/statistics/trigger-spark` | ADMIN | 无 | `{state:'DISABLED'\|'RUNNING',message,taskId,startTime}` | 顶部"刷新统计"按钮 |
| GET | `/admin/statistics/spark-status` | ADMIN | — | `{state:'READY'\|'RUNNING'\|'SUCCESS'\|'FAILED',taskId,startTime,endTime,durationMillis,message}` | 轮询直到非 RUNNING 后重载 |

> 状态机：`READY → RUNNING → {SUCCESS / FAILED}`；若 `DISABLED` 出现在 `trigger-spark` 响应中，
> 表明后端没启用跑批配置，前端按钮直接降级为"提示未启用"并不发起轮询。

## 九、风险与未覆盖项

1. **ECharts 体积**：本次仅按需引入核心模块（约 350K gzip ~120K），未启用
   tree-shaken 极致精简；如需进一步压缩，可改用 `echarts/charts` 按需
   引入 `LineChart`（已实现）或在长期方案中考虑 `unplugin-vue-components` 自动按需。
2. **轮询超时保护**：当前轮询 2s 间隔无总超时上限。若服务器 Spark 跑批卡死，
   前端会持续轮询。后续可加 `setTimeout` 兜底（建议 5 分钟）。
3. **国际化**：`qualityType` 枚举值目前直接展示英文枚举，与文档"演示用"建议一致；
   如要更友好的中文标签，前端可在 `qualityTabs` 中映射。
4. **演示数据**：未验证 `spark_demo_data.sql` 在 03:00 之外的跑批能跑出非零结果；
   建议在 P5 阶段手工触发一次 `/admin/statistics/trigger-spark` 看效果。
5. **真实 MySQL 联调**：本次未连接真实数据库；清单第 4 行的 `DatabaseIntegrationIT`
   与前端无直接耦合，但 Spark 跑批的演示依赖 MySQL 中已有帖子/评论/点赞数据。
