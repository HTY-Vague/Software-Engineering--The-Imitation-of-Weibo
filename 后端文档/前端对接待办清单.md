# 前端对接待办清单（后端 → 前端交接）

> 本文档由后端整理，列出前端需要对接或调整的接口与页面改动。
> 后端已完成的接口详见 `API接口清单.md`，本文只列前端待办项。

## 一、统计页改造（StatisticsPage.vue）

后端统计模块已改造为读取 Spark 离线分析结果，接口返回结构有变化，并新增了 4 个分析接口和 2 个跑批管理接口。前端统计页需要相应升级。

### 1. 热门帖子接口返回结构变更

接口 `GET /admin/statistics/hot-posts?limit=` 返回结构从 `ForumPost` 列表改为 `StatHotPost` 列表：

| 字段 | 类型 | 说明 |
|------|------|------|
| rankNum | int | 排名（1 开始） |
| postId | long | 帖子 ID |
| boardId | long | 板块 ID |
| authorId | long | 作者 ID |
| title | string | 帖子标题 |
| viewCount | int | 浏览量 |
| likeCount | int | 点赞数 |
| commentCount | int | 评论数 |
| hotScore | double | 热度分（点赞×2 + 评论×3 + 浏览×0.1） |
| updateTime | string | 统计更新时间 |

> 前端调整：`PostCard` 组件可能不再直接适用，建议改用排行表格展示，突出 `rankNum` 和 `hotScore`。

### 2. 新增 4 个分析接口（需在 statistics.js 中新增调用）

#### 2.1 板块活跃度排行

```
GET /admin/statistics/board-active
```

返回 `StatBoardActive[]`，按 `activeScore` 降序：

| 字段 | 类型 | 说明 |
|------|------|------|
| boardId | long | 板块 ID |
| boardName | string | 板块名称 |
| postCount | int | 帖子数 |
| viewSum | long | 浏览量总和 |
| likeSum | int | 点赞数总和 |
| commentSum | int | 评论数总和 |
| activeScore | double | 活跃度（帖子×5 + 点赞×2 + 评论×3 + 浏览×0.1） |
| updateTime | string | 更新时间 |

#### 2.2 用户活跃度排行

```
GET /admin/statistics/active-users?limit={10}
```

limit 默认 10，最大 50。返回 `StatActiveUser[]`，按 `rankNum` 升序：

| 字段 | 类型 | 说明 |
|------|------|------|
| rankNum | int | 排名 |
| userId | long | 用户 ID |
| username | string | 用户名 |
| nickname | string | 昵称 |
| postCount | int | 发帖数 |
| commentCount | int | 评论数 |
| likeCount | int | 获赞数（帖子+评论被点赞合计） |
| activeScore | double | 活跃度（发帖×5 + 评论×2 + 获赞×1） |
| updateTime | string | 更新时间 |

#### 2.3 内容质量分析

```
GET /admin/statistics/content-quality?qualityType={可选}
```

qualityType 可选值，不传返回全部：

| 值 | 说明 | 判定规则 |
|----|------|---------|
| `HIGH_LIKE_LOW_COMMENT` | 高赞低评论（优质干货） | 点赞≥10 且 评论≤5 |
| `HIGH_COMMENT_LOW_LIKE` | 高评论低赞（争议/讨论帖） | 评论≥8 且 点赞≤3 |
| `HOT` | 综合热门 | 热度≥40 |

返回 `StatContentQuality[]`：

| 字段 | 类型 | 说明 |
|------|------|------|
| postId | long | 帖子 ID |
| title | string | 帖子标题 |
| likeCount | int | 点赞数 |
| commentCount | int | 评论数 |
| viewCount | int | 浏览量 |
| qualityType | string | 质量分类 |
| updateTime | string | 更新时间 |

> 建议前端用 Tab 切换三个分类展示，或用标签筛选。

#### 2.4 每日趋势

```
GET /admin/statistics/daily-trend?days={7}
```

days 默认 7，最大 90。返回 `StatDailyTrend[]`，按 `statDate` 降序：

| 字段 | 类型 | 说明 |
|------|------|------|
| statDate | string(date) | 统计日期 |
| newUserCount | int | 当日新增用户数 |
| newPostCount | int | 当日新增帖子数 |
| newCommentCount | int | 当日新增评论数 |
| newLikeCount | int | 当日新增点赞数 |
| updateTime | string | 更新时间 |

> 建议前端用 ECharts 折线图展示 4 条趋势线（用户/帖子/评论/点赞），这是可视化亮点。

### 3. 新增 Spark 跑批管理接口（演示用）

#### 3.1 触发跑批

```
POST /admin/statistics/trigger-spark
```

无需请求体。返回：

```json
{
  "code": 200,
  "data": {
    "state": "RUNNING",
    "message": "Spark 跑批已触发，正在异步执行",
    "taskId": "spark-1782219008034",
    "startTime": "2026-06-23T20:50:08.034"
  }
}
```

state 取值：`DISABLED`（未启用配置）、`RUNNING`（已触发或已有任务在跑）。

#### 3.2 查询跑批状态

```
GET /admin/statistics/spark-status
```

返回：

```json
{
  "code": 200,
  "data": {
    "state": "SUCCESS",
    "taskId": "spark-1782219008034",
    "startTime": "...",
    "endTime": "...",
    "durationMillis": 8200,
    "message": "跑批成功\n[概览] 用户=3 ..."
  }
}
```

state 取值：`READY`（未触发）、`RUNNING`（执行中）、`SUCCESS`（成功）、`FAILED`（失败）。

> 前端建议：统计页顶部加"刷新统计"按钮 → 调 trigger-spark → 轮询 spark-status 直到非 RUNNING → 重新加载统计接口数据。按钮需防重复点击（RUNNING 时禁用）。

当前 `statistics.js` 只有 `getHotPosts`。建议补充：

```js
export const getHotPosts = (params) => http.get('/admin/statistics/hot-posts', { params })

```

> 注意：现有 `admin.js` 中也有 `getOverview` 和 `getHotPosts`，可统一迁移到 `statistics.js` 或保持现状，建议统一。

## 四、其他说明

1. **统计接口仅 ADMIN 可访问**，前端路由已有 `requiresAdmin` 守卫，无需改动。
2. **统计数据非实时**，默认每日凌晨 03:00 由 Spark 跑批刷新。概览卡片的 `updateTime` 字段可展示"最近更新于 xxx"，让用户感知数据时效。
3. **演示场景**：答辩时管理员点"刷新统计"按钮 → 等待几秒 → 页面数据刷新，可体现 Spark 分析能力。
4. **可选依赖**：每日趋势折线图建议引入 ECharts（`npm i echarts`），若不想加依赖也可用 Element Plus 的进度条简单展示。
5. **响应中文**：后端 message 字段为中文，直接展示即可（PowerShell 控制台显示乱码不影响前端浏览器）。
