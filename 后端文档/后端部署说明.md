# 后端部署说明

## 部署目标

将后端 Spring Boot 服务部署到本地、测试服务器或课程演示环境，确保 API 服务可启动、数据库可连接、接口文档可访问。

## 环境要求

| 组件 | 要求 |
|------|------|
| JDK | 21 |
| Maven | 3.8+ |
| MySQL | 8.x |
| Spark（可选，统计分析） | 4.1.2（支持 Java 21） |
| 操作系统 | Windows、Linux 均可 |

## 数据库初始化

1. 确认 MySQL 服务已启动。
2. 创建并初始化业务表：

```bash
mysql -u root -p < SoftwareEngineering.sql
```

3. 初始化 Spark 统计表（6 张 `stat_*` 表）：

```bash
mysql -u root -p software_engineering_forum < spark_stats.sql
```

4. 数据库名默认为 `software_engineering_forum`。

## 环境变量配置

PowerShell 示例：

```powershell
$env:DB_URL="jdbc:mysql://localhost:3306/software_engineering_forum?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai"
$env:DB_USERNAME="root"
$env:DB_PASSWORD="your_password"
$env:JWT_SECRET="replace_with_at_least_32_characters_secret"
$env:JWT_EXPIRATION="86400000"
$env:SERVER_PORT="8080"
```

Linux/macOS 示例：

```bash
export DB_URL='jdbc:mysql://localhost:3306/software_engineering_forum?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai'
export DB_USERNAME='root'
export DB_PASSWORD='your_password'
export JWT_SECRET='replace_with_at_least_32_characters_secret'
export JWT_EXPIRATION='86400000'
export SERVER_PORT='8080'
```

真实账号、密码和 JWT 密钥不得提交到仓库。

## 构建与启动

常规测试：

```bash
mvn test
```

构建 JAR：

```bash
mvn clean package
```

启动服务：

```bash
java -jar target/Software-Engineering-0.0.1-SNAPSHOT.jar
```

开发模式启动：

```bash
mvn spring-boot:run
```

## 验证项

1. 服务启动日志无异常。
2. `mvn test` 通过。
3. 数据库联调测试通过。
4. Knife4j UI 可访问：`http://localhost:8080/doc.html`。
5. Swagger UI 可访问：`http://localhost:8080/swagger-ui.html`。
6. 登录接口 `/auth/login` 可返回 token。
7. 携带 `Authorization: Bearer <token>` 可访问受保护业务接口。
8. 普通用户访问 `/admin/**` 被拒绝，管理员 token 可访问后台接口。

## 常见问题

| 问题 | 处理方式 |
|------|----------|
| `Access denied for user` | 检查 `DB_USERNAME`、`DB_PASSWORD` 和 MySQL 授权 |
| `Unknown database` | 执行 `SoftwareEngineering.sql` 初始化数据库 |
| `Communications link failure` | 检查 MySQL 服务、端口和 `DB_URL` |
| JWT 校验失败 | 检查 `JWT_SECRET` 是否与服务启动时一致 |
| 端口占用 | 修改 `SERVER_PORT` 后重新启动 |

## Spark 离线分析部署

### 概述

统计模块（`/admin/statistics/*` 接口）的数据来源由 Spark 离线分析程序跑批写入，不依赖 Spring Boot 在线计算。Spark 程序以独立 JVM 进程运行，通过 JDBC 读取 MySQL 业务表、聚合计算后覆盖写入 `stat_*` 统计表。每日凌晨 03:00 由 cron 自动触发。

### 服务器环境（已部署验证）

| 组件 | 路径/版本 |
|------|----------|
| Spark 安装目录 | `/opt/spark-4.1.2-bin-hadoop3/` |
| Spark 主目录（符号链接） | `/opt/spark/` |
| spark-submit | `/opt/spark/bin/spark-submit` |
| MySQL 连接器 JAR | `/opt/spark-4.1.2-bin-hadoop3/jars/mysql-connector-java-8.0.33.jar` |
| 分析程序 JAR | `/opt/forum-stats.jar` |
| 日志目录 | `/var/log/forum-spark/` |
| Java | 21.0.10+7-LTS |
| 操作系统 | CentOS（Linux 5.14.0-704.el9.x86_64） |

### 构建分析程序

分析程序是独立 Maven 工程，位于仓库 `spark-stats/` 目录：

```bash
cd spark-stats
mvn clean package -DskipTests
# 产物：spark-stats/target/spark-stats-1.0.0.jar（约 9KB，不含 Spark 运行时）
```

### 部署步骤

1. 上传 jar 到服务器：

```bash
scp spark-stats/target/spark-stats-1.0.0.jar <用户>@<服务器IP>:/tmp/forum-stats.jar
```

2. SSH 登录服务器后执行：

```bash
sudo mv /tmp/forum-stats.jar /opt/forum-stats.jar
sudo chmod 644 /opt/forum-stats.jar
sudo mkdir -p /var/log/forum-spark
sudo chown $(whoami):$(whoami) /var/log/forum-spark
```

3. 首次跑批验证：

```bash
/opt/spark/bin/spark-submit \
  --class cn.edu.zut.sparkstats.ForumSparkAnalysis \
  --master local[2] \
  --driver-memory 1g \
  /opt/forum-stats.jar \
  "jdbc:mysql://127.0.0.1:3306/software_engineering_forum?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true" \
  <数据库用户> "<数据库密码>"
```

4. 安装每日 cron（凌晨 03:00 自动跑批）：

```bash
( crontab -l 2>/dev/null | grep -v 'forum-spark-stats' ; \
  echo '0 3 * * * /opt/spark/bin/spark-submit --class cn.edu.zut.sparkstats.ForumSparkAnalysis --master local[2] --driver-memory 1g /opt/forum-stats.jar "jdbc:mysql://127.0.0.1:3306/software_engineering_forum?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true" <数据库用户> "<数据库密码>" >> /var/log/forum-spark/cron-$(date +\%Y\%m\%d).log 2>&1 # forum-spark-stats' \
) | crontab -
```

5. 手动触发跑批（课程演示用，不用等到凌晨）：

仓库提供 `spark-stats/run-spark-stats.sh` 脚本，或直接执行第 3 步的 spark-submit 命令。

### 跑批验证

跑批成功后会输出：

```
[概览] 用户=N 启用用户=N 板块=N 帖子=N 评论=N 点赞=N
[热门帖子] 写入 N 条
[板块活跃度] 写入 N 条
[用户活跃度] 写入 N 条
[内容质量] 写入 N 条
[每日趋势] 写入 N 天
==== Spark 统计分析跑批完成 ====
```

验证统计表数据：

```bash
mysql -u<用户> -p<密码> software_engineering_forum -e "SELECT * FROM stat_overview; SELECT rank_num, post_id, title, hot_score FROM stat_hot_post ORDER BY rank_num LIMIT 5;"
```

### 注意事项

- Spark 程序通过 `local[2]` 本地模式运行，不需要启动 Spark 集群，适合低配服务器。
- MySQL 连接器 JAR 需放在 Spark 的 `jars/` 目录下（已部署），否则 spark-submit 无法通过 JDBC 连 MySQL。
- 统计表采用覆盖写模式，每次跑批整表清空重写（`stat_daily_trend` 除外，按天全量重写）。
- 业务表数据变更后，最长 24 小时内统计表自动同步；演示时可手动执行跑批立即更新。
- 日志目录 `/var/log/forum-spark/` 需对执行用户可写，否则 `tee`/重定向会报 Permission denied（不影响跑批结果）。
- Spark 跑批过程中会出现 `No Partition Defined for Window operation` 警告，这是 row_number() 全局排序的正常提示，不影响结果。
