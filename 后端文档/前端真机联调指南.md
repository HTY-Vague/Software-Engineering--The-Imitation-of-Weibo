## 一、环境前置

```bash
# 演示前再启用，否则 spark 触发接口会返回 DISABLED

```

> 仓库已有 `.env.example`，把它复制成 `.env` 后填入真实值。

## 三、启动顺序

### 1. 启动后端

```powershell
# Windows 方式一：用项目自带的脚本（会读取 .env 之外的默认值）
.\run-app.bat

# 方式二：Maven 启动
$env:DB_URL="jdbc:mysql://localhost:3306/software_engineering_forum?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai"
$env:DB_USERNAME="root"
$env:DB_PASSWORD="your_password"
$env:JWT_SECRET="replace_with_at_least_32_characters_secret"
mvn spring-boot:run
```

启动后确认：

```powershell
# Knife4j
curl http://localhost:8080/doc.html -UseBasicParsing | Out-Null
# 登录探活
curl -X POST http://localhost:8080/auth/login `
  -H "Content-Type: application/json" `
  -d '{"username":"admin","password":"admin123"}'
```

预期响应：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { "token": "eyJhbGciOi...", "user": { "userId": 1, "role": "ADMIN" } }
}
```

> demo_data.sql 中 admin 的明文密码是 `Admin_123`（不是 `admin123`）。
> 对照清单里写的"admin / admin123"是文档笔误，**以 demo_data.sql 与 README 为准**。
> 登录失败时请用 `Admin_123` / `User_123` 重试。

### 2. 启动前端

```bash
cd frontend
npm install      # 首次或拉了新依赖
npm run dev
```

默认 `http://localhost:5173`。`.env` 留空即可（http.js 默认 `http://127.0.0.1:8080`）。
如需指向远程后端，新建 `frontend/.env.local`：

```
VITE_API_BASE_URL=http://你的后端IP:8080
```

### 3. 登录并访问统计页

1. 浏览器打开 `http://localhost:5173`
2. 用 `admin` / `Admin_123` 登录
3. 进入"管理后台 / 数据统计"

## 四、8 个接口的 curl 验证脚本

复制以下整段到 PowerShell 一次性执行（已含登录与 8 个统计接口）：

```powershell
$base = "http://localhost:8080"

# 1. 登录拿 token（注意大小写）
$login = Invoke-RestMethod -Method Post -Uri "$base/auth/login" `
  -ContentType "application/json" `
  -Body '{"username":"admin","password":"Admin_123"}'
$token = $login.data.token
$auth = @{ Authorization = "Bearer $token" }
Write-Host "Token: $($token.Substring(0, 20))..."

# 2. 概览
Invoke-RestMethod -Method Get -Uri "$base/admin/statistics/overview" -Headers $auth

# 3. 热门帖子
Invoke-RestMethod -Method Get -Uri "$base/admin/statistics/hot-posts?limit=10" -Headers $auth

# 4. 板块活跃度
Invoke-RestMethod -Method Get -Uri "$base/admin/statistics/board-active" -Headers $auth

# 5. 用户活跃度
Invoke-RestMethod -Method Get -Uri "$base/admin/statistics/active-users?limit=10" -Headers $auth

# 6. 内容质量（全部）
Invoke-RestMethod -Method Get -Uri "$base/admin/statistics/content-quality" -Headers $auth

# 7. 内容质量（高赞低评论）
Invoke-RestMethod -Method Get -Uri "$base/admin/statistics/content-quality?qualityType=HIGH_LIKE_LOW_COMMENT" -Headers $auth

# 8. 每日趋势
Invoke-RestMethod -Method Get -Uri "$base/admin/statistics/daily-trend?days=7" -Headers $auth

# 9. 跑批状态（演示前应是 READY）
Invoke-RestMethod -Method Get -Uri "$base/admin/statistics/spark-status" -Headers $auth

# 10. 触发跑批（未启用 SPARK_ENABLED 时返回 DISABLED）
Invoke-RestMethod -Method Post -Uri "$base/admin/statistics/trigger-spark" -Headers $auth
```

预期：
- 1–8 全部 `code: 200`，`data` 为数组或对象
- 9. 状态为 `READY` 或 `SUCCESS`/`FAILED`（取决于最近是否跑过）
- 10. 状态为 `DISABLED`（本地未启用 Spark）或 `RUNNING`（已部署 Spark）

> 9、10 必须带 `Authorization` 头，否则 401。

| 操作 | 预期 |

## 六、常见问题（FAQ）

| 现象 | 排查 |
|------|------|
| 登录返回 401 | demo_data.sql 密码是 BCrypt 哈希 `Admin_123`，不是 `admin123` |
| 统计页空白 | 看 Network，确认 8 个接口是否都 200；如果全 404，多半是 Vite 没起或 baseURL 不对 |
| 「刷新统计」一直转 | 后端 `SPARK_ENABLED=false` 时返回 `DISABLED`，前端会在 2s 内停下并弹 warning；如果真卡死，看 spark-status 是否真为 RUNNING |
| 折线图只画一次就不动了 | 切到别的 Tab 再回来应重渲染；如果 0 数据，图表会画空轴而非报错 |
| 概览「最近更新于」空 | 演示数据未导入 spark 统计表；导入 `spark_demo_data.sql` 后再触发 spark |
| CORS 报错 | 后端 Spring Security 配置应已放行 `/admin/statistics/**`；如未放行，在 SecurityConfig 显式加 `permitAll` 或开启 CORS |

## 七、P5 现场演示脚本（约 90 秒）

1. 打开 `http://localhost:5173`，登录 `admin / Admin_123`
2. 进入「数据统计」，展示 6 张概览卡 + 5 个分析区域
3. 重点指出「最近更新于 xxx」（让评审感知数据时效）
4. 点击「刷新统计」按钮 → 出现「跑批中…」状态
5. 数秒后弹"Spark 跑批完成"，5 个区域同步刷新
6. 切换「内容质量」三个 Tab 展示分类效果
7. 指着趋势折线图说明：4 条线代表 4 类增量指标，数据由 Spark 离线分析产出

> 若评审问"是不是实时"：回答"每日 03:00 定时跑批，演示时点刷新按钮可手动触发"。

## 八、未完成项与风险

1. 跑批轮询未设总超时上限，建议补 5 分钟 `setTimeout` 兜底（生产环境防卡死）。
2. 当前 StatisticsPage 单测为 0，验收前建议补 1 个组件级测试覆盖：
   - 轮询正常结束 → 状态切到 SUCCESS → loadAll 被调用
   - 触发返回 DISABLED → 立即停下 + warning
3. 服务器端 Spark 跑批脚本未在本仓库内（独立 `spark-stats/` 子工程），部署请参考 `后端文档/后端部署说明.md`。
4. 真实 MySQL 联调时若 SQL_MODE 严格，`demo_data.sql` 中的 INSERT 行为可能因 ON DUPLICATE KEY 不同略有差异，注意观察启动日志。
